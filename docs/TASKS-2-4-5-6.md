## Задача 2. Разработка приложения

### 2.1. Что входит в MVP

MVP — минимальная версия, на которой проверяем главное: будут ли люди оцифровывать гардероб и пользоваться стилистом каждый день. Маркетплейс с собственной оплатой в MVP не входит. Это осознанно: он упирается в п. 1 и самый дорогой по разработке.

| Модуль | В MVP | Позже |
| --- | --- | --- |
| Аккаунты | Вход по телефону или почте, Apple / Google / VK / Яндекс, удаление аккаунта | Семейный доступ |
| Гардероб | Фото → удаление фона → распознавание типа, цвета, материала, стиля, сезона; правка вручную; поиск и фильтры | Импорт из истории заказов |
| AI-стилист | Запрос обычным языком, образы из гардероба, замена вещей, лимит для бесплатных | Примерка на фото |
| Сегодня | Погода по геолокации, образ дня, «Предложения дня» | События календаря |
| Каталог | Товары партнёров по фиду, карточка, переход к продавцу (партнёрская ссылка) | Собственная оплата, корзина на несколько продавцов |
| Лента | Новости, публикация образов, лайки, жалобы | Каналы, комментарии |
| Подписка | — | Этап 3 |
| Админка | Модерация жалоб, управление новостями и каталогом | Кабинет продавца |

### 2.2. Структура ТЗ

ТЗ собираем в отдельном документе по этой структуре. Демо-версия уже служит кликабельным прототипом: экраны и сценарии в ТЗ ссылаются на неё.

1. Цели MVP и метрики успеха: доля пользователей, добавивших 20+ вещей; запросы к стилисту в неделю; удержание на 7-й и 30-й день.
2. Роли: пользователь, модератор, администратор. Продавец — со следующего этапа.
3. Пользовательские сценарии — по экранам демо.
4. Функциональные требования по модулям из таблицы 2.1.
5. Модель данных: пользователь, вещь, образ, товар, продавец, публикация, жалоба.
6. Интеграции:
   - распознавание и удаление фона;
   - языковая модель для стилиста;
   - погода;
   - карты и геолокация;
   - push-уведомления (APNs, FCM, RuStore Push);
   - фиды партнёров.
7. Нефункциональные требования:
   - хранение персональных данных в России ⚖️ п. 1;
   - время ответа стилиста;
   - нагрузка на старте;
   - резервные копии.
8. Платежи и маркировка — **открытые вопросы до ответа по п. 1**: эквайринг, агентская схема, «Честный знак».
9. Критерии приёмки и план тестирования.
10. Публикация: RuStore и TestFlight для пилота, затем App Store, Google Play, AppGallery.

### 2.3. Что может сделать AI, а где нужны люди

| Работа | AI-агенты (как это демо) | Нужен человек |
| --- | --- | --- |
| Экраны приложения, вёрстка, логика интерфейса | Да, основная часть | Ревью, решения по UX |
| Серверная часть, API, база данных | Да, по чёткому ТЗ | Архитектура, ревью безопасности |
| Интеграции (распознавание, LLM, погода, push) | Да, код интеграций | Выбор поставщиков, договоры, ключи |
| Качество распознавания и ответов стилиста | Частично: промпты, тест-наборы | Оценка качества на реальных вещах |
| Инфраструктура в российском облаке, CI/CD, мониторинг | Частично | Настройка доступов, ответственность за продакшен |
| Платежи и чеки | Код интеграции | Договоры, тестирование с банком ⚖️ п. 1 |
| Тестирование на реальных устройствах | Автотесты | Ручной тест на iPhone и Android |
| Публикация в магазинах | Сборки, тексты, скриншоты | Аккаунты разработчика, ответы модерации |
| Дизайн, брендинг, логотип | Черновые варианты | Дизайнер для финального стиля |

**Вывод:** AI справится с большей частью кода. Но кто-то должен отвечать за архитектуру, безопасность, продакшен и итоговое качество. Чисто на AI выпускать продукт с платежами и персональными данными рискованно.

### 2.4. Варианты разработки

| | A. AI-агенты + техлид | B. Студия на аутсорсе | C. Собственная команда |
| --- | --- | --- | --- |
| Состав | Техлид (full-stack, договор ГПХ/ИП) + AI-агенты; дизайнер и QA на часть времени | Студия под ключ по ТЗ | 3–4 разработчика + QA + дизайнер |
| Срок до MVP | 3–4 месяца | 4–6 месяцев (с поиском и согласованиями) | 3–4 месяца, но плюс время на найм |
| Деньги | Ниже всего | Выше всего, зато фиксированная цена | Высокие, постоянные расходы |
| Скорость правок | Высокая | Низкая: через менеджера и допсоглашения | Высокая |
| Риски | Зависимость от одного техлида | Код и знания остаются у студии; правки дорогие | Найм и ФОТ до проверки спроса |

**Рекомендация: вариант A.** Он быстрее всего, дешевле всего и совпадает с приоритетом п. 8 (аутсорс, без штата). Риск зависимости от одного человека закрываем так: код с первого дня в нашем репозитории, документация в `docs/`, второй разработчик на ревью по часам.

### 2.5. Оценка объёма MVP

Оценка в часах работы человека при классической разработке. С AI-агентами ручная работа над кодом сокращается; закладываем экономию 30–50% как гипотезу, которую проверим на первом месяце.

| Блок | Часы |
| --- | --- |
| Сервер, аккаунты, хранение фото, API | 120–160 |
| Гардероб: загрузка, удаление фона, распознавание | 120–180 |
| AI-стилист на языковой модели | 120–200 |
| Каталог партнёров: импорт фидов, поиск, карточка | 80–120 |
| Лента: публикации, лайки, жалобы | 60–100 |
| Мобильное приложение: перевод демо на реальные данные | 120–160 |
| Админка и модерация | 40–80 |
| Инфраструктура в РФ, CI/CD, мониторинг | 40–80 |
| Тестирование, сборки, публикация в RuStore и TestFlight | 60–100 |
| **Итого** | **760–1 180** |

**Деньги до MVP** = часы × ставка + постоянные расходы. Ставки берём из 2–3 коммерческих предложений.

- Дизайн и QA на часть времени: [уточнить].
- Сервисы в месяц: облако, языковая модель (оплата за запросы), распознавание и удаление фона, push, погода — [уточнить по тарифам поставщиков; зависит от числа пользователей пилота].

### 2.6. Как принимаем решение и ищем команду

1. Получаем ответы по п. 1 и закрываем открытые вопросы ТЗ.
2. Делаем ТЗ на MVP (2.2).
3. Ищем техлида: рекомендации, профильные сообщества, фриланс-площадки.
   - Требования: React Native / Expo, Node.js или Python, опыт публикации в магазинах, опыт с LLM — плюс.
4. Даём оплачиваемое тестовое задание на 8–16 часов: перевести один экран демо на реальный сервер.
5. Договор ГПХ или ИП. Код — в нашем репозитории, права на код — у нас.
6. Первый месяц — контрольная точка: сверяем скорость с оценкой 2.5 и решаем, нужны ли ещё люди.

## Задача 4. Тарифы подписки

### 4.1. Принцип

Бесплатная версия полезна каждый день — так человек возвращается и наполняет гардероб. Premium продаёт три вещи:
1. **Без ограничений** — стилист, планировщик, аналитика.
2. **Без рекламы** — связь с задачей 5.
3. **Окупаемость** — кэшбэк и бесплатная доставка в маркете.

### 4.2. Что бесплатно, а что в Premium

| Функция | Бесплатно | Premium |
| --- | --- | --- |
| Гардероб | Без ограничения числа вещей | Без ограничения |
| Распознавание вещей по фото | Да | Да |
| Образ на сегодня с учётом погоды | Да | Да |
| AI-стилист | 3 запроса в день | Без лимита |
| Планировщик образов | Только на сегодня | На неделю, поездки, список вещей в чемодан |
| Образы к событиям календаря | 1 событие вперёд | Все события |
| «Стоит ли покупать?» (фото или ссылка) | 3 проверки в месяц | Без лимита |
| Примерка образа на своём фото | 1 пробная | Без лимита |
| Аналитика гардероба | Чего не хватает | Цена выхода, вещи без дела, цвета, сезоны |
| Реклама | Есть (см. задачу 5) | **Нет** |
| Маркет, покупка образа, бренды | Да | Да + кэшбэк 5% и бесплатная доставка |
| Проверка подлинности брендовых вещей | Платно | Со скидкой [уточнить %] |
| Лента: чтение, публикации | Да | Да + отметка Premium в профиле |

**Почему так:**
- Гардероб и распознавание бесплатны всегда: без вещей в гардеробе нет ни подписки, ни продаж.
- Всё дорогое по затратам на AI (стилист, примерка, проверка вещей) ограничено лимитом. Пользователь пробует бесплатно и упирается в лимит в момент, когда функция ему нужна.

### 4.3. Цены

| Тариф | Цена | В месяц | Скидка |
| --- | --- | --- | --- |
| 1 месяц | 699 ₽ | 699 ₽ | — |
| 3 месяца | 1 790 ₽ | 597 ₽ | −15% |
| 6 месяцев | 3 290 ₽ | 549 ₽ | −22% |
| 12 месяцев | 5 870 ₽ | 489 ₽ | −30% |
| Пакет «Отпуск» (разово) | 399 ₽ | — | Premium-функции на 14 дней |

- Пробный период — 7 дней на любом тарифе.
- По умолчанию выбран тариф на 12 месяцев.
- Периоды 1, 3, 6 и 12 месяцев поддерживают и App Store, и Google Play, так что тарифы одинаковые во всех каналах.

### 4.4. Правила

- **Подписка закончилась:** гардероб, образы и публикации сохраняются. Отключаются только Premium-функции, и возвращается реклама.
- **Отмена:** в один клик, с напоминанием за 3 дня до списания и чеком.
- **Кэшбэк:** бонусы на покупки в маркете, не деньги. Сгорают через [уточнить] месяцев. Условия — в оферте ⚖️ п. 1.

### 4.5. Когда предлагаем подписку

- 4-й запрос к стилисту за день.
- Запрос про поездку или неделю.
- 4-я проверка «Стоит ли покупать?» за месяц.
- После 30 добавленных вещей: «гардероб готов к подробному анализу» с размытыми цифрами.
- В корзине: «с Premium доставка бесплатно и вернулось бы N ₽».
- Не показываем: при первом запуске, во время оплаты, чаще одного раза в день.

### 4.6. Что проверяем после запуска

| Гипотеза | Как проверяем |
| --- | --- |
| 699 ₽ в месяц — не слишком дорого | A/B: 699 против 499 ₽, смотрим выручку на пользователя, а не только конверсию |
| Годовой тариф — самый популярный | Доля годовых среди новых подписок |
| Лимит 3 запроса в день — правильный | A/B: 3 против 5, смотрим конверсию и удержание бесплатных |
| «Без рекламы» продаёт подписку | Конверсия с рекламой и без |

Цели по метрикам: конверсия в пробный период, переход из пробного в платный, отток на 1-м и 3-м месяце — [уточнить после пилота].

## Задача 5. Реклама в приложении — техническая часть

Продажа рекламы брендам и договоры — на направлении «Право и маркетинг». Здесь — форматы, поставщики, интеграция и правила показа.

### 5.1. Форматы

| Формат | Где | Правила |
| --- | --- | --- |
| Полноэкранная (interstitial), закрыть через 10–15 с | При переходах между разделами | Не при первом запуске, не в корзине и оплате, не чаще раза в 5 минут и [уточнить] раз в день |
| Нативные карточки | Лента (каждая 6–8-я публикация), маркет (блок «Реклама»), «Сегодня» (одна карточка) | Всегда с пометкой «Реклама», в стиле приложения |
| Баннер | Низ экранов списков | Только если нативных мало |
| За вознаграждение (rewarded) | По желанию пользователя | Например: «посмотри рекламу — +1 запрос к стилисту». Мягкий путь к подписке |

**Не смешиваем рекламу с советами AI.** Стилист и «Предложения дня» рекламу не показывают — это правило продукта.

### 5.2. Поставщики рекламы для российской аудитории

| Сеть | Что даёт | Комментарий |
| --- | --- | --- |
| Рекламная сеть Яндекса (Yandex Mobile Ads SDK) | Все форматы из 5.1 | Основной вариант для России |
| VK Ads (бывший myTarget) | Баннеры, полноэкранная, нативная | Второй источник для заполняемости |
| Прямые продажи брендам | Нативные карточки и размещения в ленте | Дороже всего; продаёт маркетинг |
| Google AdMob | — | Для России не подходит: Google с 2022 года не показывает рекламу пользователям в России. Можно использовать для других стран |

### 5.3. Как это встраивается технически

- Рекламные SDK — это нативные модули. Для них нужна собственная сборка через EAS Build. В демо через Expo Go и в веб-версии реклама работать не будет; для веба — отдельные форматы РСЯ.
- **Медиация:** один код показа, сеть выбирается по цене. Начинаем с одной сети (Яндекс), вторую подключаем, когда появится трафик.
- **Флаг Premium:** сервер отдаёт «показывать рекламу: да/нет». Реклама выключается сразу после оплаты подписки.
- **Частота показов** настраивается на сервере, без выпуска новой версии.
- **Маркировка (ERID).** Для рекламы из сетей маркировку берёт на себя сеть. Для прямых размещений брендов маркируем сами через оператора рекламных данных ⚖️ п. 1.
- **Магазины приложений:** Apple требует запрос разрешения на отслеживание (ATT), если реклама персонализированная. В анкетах о данных указываем рекламные SDK.

### 5.4. Оценка доходности

Выручка от рекламы в месяц = показы × eCPM / 1000. Число показов зависит от лимитов частоты из 5.1, eCPM (доход за 1 000 показов по формату) — [уточнить в кабинете РСЯ после подключения]. В бизнес-плане реклама пока учтена одной строкой вместе с продвижением; уточним после первого месяца показов.

## Задача 6. Инструменты для продавцов — механика и интеграции

Условия договора, комиссии в оферте и соответствие 289-ФЗ — на направлении «Право». Здесь — как это работает в продукте.

### 6.1. Портрет продавцов

| Тип | Что важно | Как подключаем |
| --- | --- | --- |
| Небольшие магазины и шоурумы | Простое подключение, без программиста | Ручное добавление или Excel/CSV |
| Бренды | Аудитория «под гардероб», аналитика | Фид YML/CSV, API |
| Ресейлеры | Каталог брендов, проверка подлинности | Ручное добавление, быстрые объявления с телефона |
| Частные лица | Продать вещь из своего гардероба в пару нажатий | «Продать» прямо из карточки вещи в гардеробе |

### 6.2. Подключение продавца

1. Регистрация в веб-кабинете → проверка: ИНН, статус ИП / самозанятого / юрлица; для частных лиц — по правилам ⚖️ п. 1 и 289-ФЗ.
2. Согласие с офертой и правилами площадки, включая запрет контрафакта (связь с задачей 7).
3. Профиль магазина: название, описание, город, сроки отправки — каждый продавец ставит свои.
4. Товары: вручную, Excel/CSV, фид YML или API.
5. Реквизиты для выплат ⚖️ п. 1: эквайринг и схема выплат.

### 6.3. Кабинет продавца (веб)

- Товары и остатки, массовое редактирование.
- Заказы: новые, на отправке, в пути, возвраты; печать накладных.
- Аналитика:
  - продажи и откуда пришли покупатели (AI-образ, каталог, бренд, лента);
  - сколько раз товар попал в образы;
  - конверсия.
- Отзывы и ответы на них.
- Финансы: выплаты, удержанная комиссия, акты.
- Продвижение (6.4).

### 6.4. Как зарабатываем на продавцах

| Источник | Как работает |
| --- | --- |
| Комиссия с продажи | Процент от суммы заказа. Базовое допущение — 12%, диапазон 10–15%; может зависеть от категории [уточнить] |
| Продвижение товара | Товар выше в каталоге и в блоке «Реклама» маркета. Оплата за клики или пакетами показов. Только тем, кому вещь подходит по гардеробу |
| Продвижение магазина | Магазин первым в разделе «Магазины» и в ленте маркета; публикации магазина в ленте с пометкой «Реклама» |
| Платная аналитика | Расширенные отчёты: спрос по брендам и категориям, что ищут и не находят |
| Проверка подлинности | Платная услуга для дорогих вещей (связь с задачей 7) |

**Платное продвижение никогда не влияет на советы AI-стилиста.** Это закреплено в коде и в правилах для продавцов.

### 6.5. Интеграции с учётом продавца

- **Импорт товаров:** YML-фид (стандарт для российских маркетплейсов), CSV/Excel, API.
- **Учётные системы:** МойСклад и 1С через их API или готовые коннекторы — синхронизация остатков и заказов. Делаем после MVP по запросам первых продавцов.
- **CRM продавца:** вебхуки о заказах и статусах, чтобы продавец получал заказы в свою систему.
- **Доставка:** интеграция с агрегатором служб доставки [уточнить выбор], трекинг в карточке заказа покупателя.

### 6.6. Ответственность продавца

Продавец сам указывает срок отправки. Система следит за сроками автоматически:

| Нарушение | Автоматическая реакция |
| --- | --- |
| Заказ не отправлен в срок | Напоминание → автоматическая отмена и возврат денег покупателю |
| Повторные просрочки | Понижение в выдаче, отметка в рейтинге продавца |
| Систематические нарушения или жалобы на подделки | Приостановка продаж с возможностью обжаловать |
| Денежные штрафы | ⚖️ п. 1: можно ли и в каком виде. 289-ФЗ регулирует отношения площадки и продавцов, включая досудебное обжалование решений площадки |

Рейтинг продавца складывается из отправок в срок, отзывов, возвратов и жалоб. Он показывается покупателю и влияет на место в выдаче.

### 6.7. Привлечение первых продавцов

1. Первые 20–30 продавцов вручную: шоурумы, ресейлеры, локальные бренды. Им — сниженная комиссия на первые [уточнить] месяца.
2. Аргумент для продавца — покупатели, которым вещь подходит по гардеробу, и статистика попадания товара в образы.
3. Частные лица — через кнопку «Продать» в гардеробе для вещей, которые лежат без дела. Это бесплатный поток предложений.
